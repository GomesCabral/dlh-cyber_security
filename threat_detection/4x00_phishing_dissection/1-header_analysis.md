# Header Analysis

## Email 2 — meddefense-portal.com

### Header Evidence

- From: "MedDefense IT Security" <noreply@meddefense-portal.com>
- Return-Path: <noreply@meddefense-portal.com>
- Sending IP: 91.234.99.107
- X-Mailer: PHPMailer 6.6.0
- Message-ID: <PHP-5D7E2F4A@meddefense-portal.com>

### Received Chain Summary

1. The message was generated locally through PHPMailer on mail.meddefense-portal.com.
2. mail.meddefense-portal.com [91.234.99.107] delivered the message to mx01.meddefense.com.
3. mx01.meddefense.com passed the message to the internal inbound-relay.meddefense.com.

### Anomalies

- [HIGH] The message claims to represent "MedDefense IT Security" but originates from the external domain meddefense-portal.com instead of the legitimate meddefense.com domain.
- [HIGH] SPF failed because 91.234.99.107 was not authorized to send mail for meddefense-portal.com.
- [HIGH] DMARC failed.
- [HIGH] No DKIM signature was present.
- [MEDIUM] The message was generated using PHPMailer 6.6.0 rather than MedDefense's internal Exchange infrastructure.
- [MEDIUM] The Message-ID uses the PHPMailer-style format `PHP-5D7E2F4A@meddefense-portal.com`.
- [MEDIUM] The message sets X-Priority and Importance to High.

### Conclusion

E2 shows strong phishing indicators. Although the visible sender claims to be MedDefense IT Security, the message originated from external IP 91.234.99.107 using the lookalike domain meddefense-portal.com and PHPMailer. SPF and DMARC failed and no DKIM signature was present. The headers do not match legitimate MedDefense internal mail infrastructure.


## Email 3 — outlook-protection.com

### Header Evidence

- From: "Microsoft Account Protection" <security@outlook-protection.com>
- Return-Path: <security@outlook-protection.com>
- Sending IP: 51.38.42.17
- X-Mailer: PHPMailer 6.6.0
- Message-ID: <PHP-9F2D7E1B@outlook-protection.com>

### Received Chain Summary

1. The message was generated through PHPMailer on wp-admin.outlook-protection.com.
2. mail.outlook-protection.com [51.38.42.17] delivered the message to mx01.meddefense.com using ESMTPS.
3. mx01.meddefense.com passed the message to the internal inbound-relay.meddefense.com.

### Anomalies

- [HIGH] The visible sender claims to be "Microsoft Account Protection", but the sending domain is outlook-protection.com rather than an established Microsoft mail domain.
- [HIGH] The sending infrastructure is mail.outlook-protection.com [51.38.42.17], with the message generated by PHPMailer.
- [MEDIUM] The Message-ID uses the same PHPMailer-style `PHP-*` pattern observed in other suspicious messages.
- [MEDIUM] The internal generating host is named wp-admin.outlook-protection.com, suggesting web-hosted or WordPress-style infrastructure rather than normal Microsoft 365 mail infrastructure.
- [MEDIUM] The message uses X-Priority 1 (Highest).
- [MEDIUM] SPF, DKIM and DMARC pass, but they only authenticate outlook-protection.com; they do not prove that the sender is Microsoft.

### Conclusion

E3 is suspicious despite passing SPF, DKIM and DMARC. The authentication results confirm that the message is authorized for outlook-protection.com, not that the domain belongs to Microsoft. The claimed Microsoft identity, PHPMailer infrastructure, PHP-style Message-ID and external sending IP justify further investigation.

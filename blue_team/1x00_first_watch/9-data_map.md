# Data Map

| Data Category | Classification | At Rest (where) | In Transit (how) | In Use (by whom, on what) | Current Protection | Protection Gaps |
|---------------|---------------|-----------------|------------------|---------------------------|-------------------|-----------------|
| Patient Medical Records | Restricted | EHR PostgreSQL database (ehr-db-01) | Between EHR servers and clinical workstations over the internal network | Physicians and nurses using the EHR on clinical workstations | Active Directory authentication, firewall, scheduled backups | Unattended EHR sessions at nurse stations expose patient data in use; flat network increases exposure if a workstation is compromised |
| Medical Imaging Data | Restricted | PACS server | MRI workstation sends studies to the PACS server | Radiologists using PACS workstations | PACS server, authenticated access | MRI workstation runs Windows XP and shares the same network as standard workstations, increasing compromise risk |
| Billing and Insurance Data | Restricted | billing-srv-01 | Finance staff access billing services over the internal network | Finance department using billing application | Authentication, firewall, backups | Previous ransomware and cryptomining incidents, outdated Ubuntu 18.04 system and broad network exposure |
| Employee HR Records | Confidential | File server and Microsoft 365 | Accessed over the corporate network | HR staff using office workstations | Password policy and Active Directory authentication | Flat network and previously observed unmanaged devices increase exposure |
| System Credentials | Restricted | Active Directory | Authentication requests between clients and domain controllers | IT administrators and all authenticated users | Password policy, account lockout and Active Directory | Network closet contained exposed switch credentials; no MFA for most users |
| Audit Logs | Confidential | Windows Event Logs, Linux logs and firewall logs | Log data generated by systems and devices | IT administrators reviewing logs | Local log collection | No centralized SIEM or automated alerting delays incident detection |
| Public Website Data | Public | web-srv-01 | HTTPS connections between patients and the website | Patients and public users | Firewall and web server controls | Website was previously defaced, demonstrating insufficient protection of public-facing services |

## Data Risk Summary

MedDefense's greatest data protection weakness is the handling of patient medical records while they are **in use**. Protected health information is classified as **Restricted**, yet previous assessments identified unattended EHR sessions, flat network architecture, legacy Windows XP systems and insufficient network segmentation. These weaknesses create opportunities for unauthorized access and lateral movement, exposing highly sensitive patient data despite existing preventive controls.

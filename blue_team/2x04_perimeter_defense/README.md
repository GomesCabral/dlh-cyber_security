# MedDefense Perimeter Defense

This project builds and validates local network controls and produces structured
JSON evidence for the MedDefense Module 3 analyst handoff.

## Task 0 — Network Baseline

`0-network_baseline.sh` captures the hardened endpoint's current local network
view without modifying network or system state. It records active interfaces,
routes, neighbors, listening sockets, established TCP connections and DNS
resolver configuration in `network_baseline.json`.

### Dependencies

- Bash
- iproute2 (`ip` and `ss`)
- jq
- systemd tools (`systemctl` and `resolvectl`) when `systemd-resolved` is used

### Usage

```bash
chmod +x 0-network_baseline.sh
sudo ./0-network_baseline.sh
jq . network_baseline.json
```

Run the script with `sudo` so that `ss -p` can resolve process names and PIDs
for sockets owned by other users. The optional first argument changes the output
path:

```bash
sudo ./0-network_baseline.sh evidence/network_baseline.json
```

## Task 1 — Attack Surface Map

`1-attack_surface.sh` enriches every listener in `network_baseline.json` with
its binary, Debian package, systemd service unit, function, criticality and
exposure flags. It writes the resulting report to `attack_surface.json`.

### Inputs

- `network_baseline.json` — generated by Task 0
- `service_catalog.json` — maps sockets and processes to service functions
- `service_criticality.json` — maps services to `critical`, `high`, `medium`
  or `low`

The task-provided `service_catalog.json` and `service_criticality.json` files
must be in the current directory. The script accepts alternate paths as four
ordered arguments: baseline, service catalog, criticality catalog and output.

### Processing

For every listening socket, the script:

1. Reads its protocol, bind address, port, process name and PID from the Task 0
   baseline.
2. Resolves the executable through `/proc/PID/exe`.
3. Resolves the owning Debian package with `dpkg -S`.
4. Resolves the associated systemd unit and its configuration with
   `systemctl show`.
5. Assigns a function and criticality from the supplied catalogs.
6. Adds exposure flags for databases or RPC services bound to `0.0.0.0` and
   for Telnet, FTP, SNMPv1, SNMPv2c, rlogin and NFS v2/v3.

Unknown functions remain in the report and are counted separately for analyst
triage.

### Usage

```bash
chmod +x 1-attack_surface.sh
shellcheck 1-attack_surface.sh
sudo ./1-attack_surface.sh
jq . attack_surface.json
```

Run with `sudo` because binary and cgroup information under `/proc` may not be
readable for processes owned by other users.

Optional explicit paths can be supplied in this order:

```bash
sudo ./1-attack_surface.sh \
  network_baseline.json \
  service_catalog.json \
  service_criticality.json \
  attack_surface.json
```

### Output structure

```json
{
  "generated_at": "2026-08-14T11:36:23Z",
  "hostname": "billing-srv-01",
  "sockets": [
    {
      "proto": "tcp",
      "port": 3306,
      "bind_addr": "0.0.0.0",
      "process": "mysqld",
      "package": "mysql-server",
      "function": "database",
      "criticality": "critical",
      "exposure_flags": [
        "bound_0.0.0.0",
        "database_exposed"
      ]
    }
  ],
  "summary": {
    "total_sockets": 1,
    "flagged_sockets": 1,
    "unknown_functions": 0,
    "flagged_by_severity": {
      "critical": 1,
      "high": 0,
      "medium": 0,
      "low": 0
    }
  }
}
```

### Useful queries

Show only flagged sockets:

```bash
jq '.sockets[] | select(.exposure_flags | length > 0)' attack_surface.json
```

Show functions that still need analyst classification:

```bash
jq '.sockets[] | select(.function == "unknown")' attack_surface.json
```

Show the report summary:

```bash
jq '.summary' attack_surface.json
```
